# Правила работы с репозиторием

## Источники требований

- `PRODUCT.md` — источник продуктовых требований.
- `TECH_RESEARCH.md` — технические ограничения, исследовательские гипотезы, эксперименты и принятые решения.
- Перед выполнением задачи ознакомься с относящимися к ней разделами этих документов.
- Если требования противоречат друг другу, отсутствуют или требуют существенного технического решения, сообщи об этом владельцу проекта. Не изменяй требования самостоятельно.

## Реализация

- Выполняй только поставленную задачу, соблюдая её ограничения и критерии приёмки.
- Не добавляй сторонние зависимости, не расширяй область изменений и не принимай существенные архитектурные решения без согласования.
- Экспериментальный код размещай в `experiments/`. Конкретное расположение и границы каждого PoC определяются его техническим заданием.
- Не переноси экспериментальные решения в production-код без отдельного решения.
- Следуй согласованному плану, если задача выполняется по предварительно утверждённому плану.

## Проверка результатов

- После изменений выполняй применимые проверки, включая сборку и тесты, если среда позволяет.
- Не объявляй задачу успешно завершённой только на основании отсутствия ошибок компиляции.
- Не выдавай предположения за факты и не придумывай результаты проверок или измерений.
- Не считай исследовательскую гипотезу подтверждённой без предусмотренных экспериментом проверок.

## Отчёт о выполнении

После каждой задачи кратко сообщай:

1. Что реализовано и какие файлы изменены.
2. Какие проверки выполнены и их результаты.
3. Что осталось непроверенным.
4. Какие проблемы, ограничения или риски обнаружены.

## Контроль изменений

- Не изменяй продуктовые требования и зафиксированные технические решения без явного указания.
- Не выполняй Git commit, push, reset или другие потенциально разрушительные операции без явного разрешения владельца проекта.
- Окончательная приёмка работы и решение о пригодности экспериментальных технологий остаются за владельцем проекта.
- Любой значительно влияющий на продукт блок кода (новая фича, PoC, существенное изменение уже имеющегося функционала и тп) должно выполняться в отдельной созданной под эту задачу ветке. Не создавай ветки самостоятельно без явного указания владельца проекта. Перед началом работы над подобной задачей проверяй ветку, если она не соответствует данному условию - сообщи владельцу и запроси решение о ветке.
