# PoC-01 — Native Text Engine Baseline

Изолированный эксперимент по разделу 6 `../../TECH_RESEARCH.md`: `NSTextView` + TextKit 2,
одно окно, обычный текст и загрузка UTF-8 только в память. Не является будущим приложением.
Нет подсветки Markdown, сохранения, поиска, вкладок, восстановления сессии и файловых наблюдателей.
**Open заменяет текущий текст, закрытие/выход отбрасывают правки без подтверждения.**

## Среда и сборка

- macOS 27.0+, Apple Silicon (`arm64`), Xcode совместимой ветки 27.x.
- Встроенные AppKit, Foundation, OSLog; генератор использует CryptoKit. Внешних зависимостей нет.
- Swift language mode 5 с явной изоляцией AppKit на MainActor.
- Ad hoc подпись (`CODE_SIGN_IDENTITY = -`), без Developer Team.
- App Sandbox включён, выбранные пользователем файлы доступны только для чтения.

Все команды ниже выполняются из `experiments/poc-01-textkit2/`.

```sh
xcodebuild -project PoC01.xcodeproj -scheme PoC01 \
  -configuration Debug -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath DerivedData build

xcodebuild -project PoC01.xcodeproj -scheme PoC01 \
  -configuration Debug -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath DerivedData test

xcodebuild -project PoC01.xcodeproj -scheme PoC01 \
  -configuration Release -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath DerivedData build

open DerivedData/Build/Products/Release/PoC01.app
```

Общая схема хранится в Git. XCTest target — **не sandboxed**: он компилирует те же
исходники редактора, загрузчика и диагностики, но не запускает приложение через его точку входа.
Он не проверяет выдачу доступа через системный Open Panel. Для AppKit-тестов нужна рабочая
графическая пользовательская сессия. Ошибки testmanagerd/прав среды исполнения фиксировать
отдельно от ошибок приложения и движка. Не отключать sandbox приложения ради прохождения тестов.

## Тестовые документы

```sh
xcrun swift Scripts/GenerateFixtures.swift TestData/generated TestData/manifest.json
xcrun swift Scripts/VerifyFixtures.swift
```

Первая команда требует свежую папку назначения: существующие документы не перезаписываются.
Если документы уже сгенерированы, можно сразу открывать их или выбрать другую свежую папку.
`VerifyFixtures.swift` создаёт два собственных временных набора и удаляет их после проверки.
При ограничении записи в системный module cache можно передать Swift параметр
`-module-cache-path /tmp/poc01-swift-module-cache` перед путём скрипта.

| Файлы | Размер каждого в байтах UTF-8 | Окончания |
|---|---:|---|
| `baseline-100000-{lf,crlf}.md` | 100 000 | LF / CRLF |
| `baseline-1000000-{lf,crlf}.md` | 1 000 000 | LF / CRLF |
| `baseline-5000000-{lf,crlf}.md` | 5 000 000 | LF / CRLF |
| `stress-1000000-no-newline.txt` | 1 000 000 | Нет, одна строка |

Размеры десятичные. Базовый блок содержит короткие и длинные строки, пустые строки, кириллицу,
латиницу, emoji с модификатором/ZWJ и составной `e` + U+0301. Блок повторяется целиком;
остаток заполняется ASCII с целым окончанием строки, когда оно помещается. Стресс-файл отдельный.
Нет случайности, часов, нормализации Unicode или зависимости от локали.

`TestData/manifest.json` хранит версию генератора, размер, число строк и SHA-256 каждого файла.
Число строк = число LF плюс один для непустой последней строки без LF; CRLF считается один раз.
Генератор сравнивает результат с манифестом. Независимый проверяющий скрипт дополнительно
проверяет байты двух генераций, UTF-8, точные размеры, окончания, Unicode, число строк и отказ
перезаписи. В Git хранить скрипты и манифест; `TestData/generated/` уже исключён из Git.

## Работа и диагностика

`Cmd+O` — загрузить `.md` или `.txt`; `Cmd+Z` / `Shift+Cmd+Z` — Undo/Redo;
`Cmd+X/C/V/A` — обычные операции; `Cmd+W/Q` — закрыть/выйти.
Остальные функции будущего редактора намеренно отсутствуют.

Создание: `NSTextView(usingTextLayoutManager: true)`. Диагностика читает только
`textLayoutManager`, не обращается к TextKit 1 layout manager ни напрямую, ни через контейнер.
Наблюдатели will/did-switch регистрируются до создания view, ранние события фильтруются
по идентичности созданного редактора. Затем события других text views игнорируются.
В обработчике перехода layout-объекты не запрашиваются. `fallbackCount` считает did-switch;
will-switch также всегда логируется. Переход не скрывается пересозданием view.

Контрольные точки: создание, настройка, загрузка, редактирование (не чаще раза в 0,5 с),
Undo и Redo. Повторные проверки не копируют документ и не считают его хеш.
Факт отсутствия TextKit 2 выводится как ошибка; отсутствие уведомлений само по себе не считается успехом.

Перед запуском приложения откройте отдельный Terminal:

```sh
log stream --level info --style compact --predicate 'subsystem == "local.md-editor.PoC01"'
```

Можно также использовать Console с фильтром по subsystem. Строки `checkpoint=...`
содержат `textKit2`, счётчик fallback и uptime; `FALLBACK` — фазу перехода.
Сообщение `load` содержит размер и времена чтения, декодирования, установки текста.
Содержимое и полный путь файла не логируются. Не выполняйте в отладчике выражения,
читающие свойство TextKit 1 layout manager; для расследования fallback используйте уведомления.
Сбор стека и отладочные запуски не смешивать с замерами производительности.

## Что измеряется автоматически

Монотонные часы: чтение `Data`, отдельно декодирование UTF-8, отдельно присваивание строки редактору.
Чтение синхронное, на главном потоке — осознанное упрощение этого опыта. Настройка выделения,
прокрутка и сброс Undo не включаются во время присваивания. Нет принудительного полного layout.
Временные буферы чтения не удерживаются после загрузки; Undo очищается при каждой новой загрузке.
**Время присваивания не является временем готовности к вводу или завершения отрисовки.**

Автотесты проверяют безопасные повторные запросы состояния, буквальную вставку символов,
отключённые подстановки, Unicode, выделение/удаление, Undo/Redo, перенос текста через частный
pasteboard, успешную загрузку, ошибки UTF-8/отсутствующего файла, сброс Undo и неизменность
исходных байтов. Тест вставки вызывает text-input API посимвольно, а не физические события клавиатуры.
Тесты не заменяют проверку IME, системных предпочтений и реального ввода пользователем.

## Ручная проверка F-01…F-07

Использовать Release без отладчика. Скопировать `RESULTS_TEMPLATE.md` в отдельный отчёт;
не заполнять отсутствующие измерения нулями.

1. **F-01:** запустить `.app` указанной командой. Проверить одно окно, фокус редактора и меню.
2. **F-02, F-05:** набрать с клавиатуры, не вставить готовой строкой:
   `"double" 'single' -- --- ... (c) teh -> <- != <= >=`, обратные кавычки, `**bold**`,
   `_em_`, `~~s~~`, `#`, `[]()`, `![x](url)`. После последовательностей нажимать пробел/Enter,
   перемещать курсор. Кавычки должны остаться прямыми, дефисы — ASCII, опечатки — неисправленными.
   Проверить кириллицу, emoji, составной Unicode, выделение, удаление, обычный copy/paste.
   Зафиксировать системные настройки подстановок; желательно проверить и при включённых системных
   smart quotes/dashes/autocorrection. Не включать подстановки вручную в контекстном меню редактора.
3. **F-03:** несколько раз изменить текст, выполнить Undo/Redo через меню и клавиатуру.
4. **F-04, F-05:** через Open загрузить все шесть обычных файлов, затем отдельный стресс-файл.
   Проверить прокрутку, курсор и выделение в начале/середине/конце, набор и удаление.
   Отмена Open сохраняет текущий текст; ошибочный UTF-8/ошибка доступа тоже сохраняют его.
5. **F-06:** сохранить журнал контрольных точек всех этих этапов. При fallback записать файл,
   действие, фазу перехода и точную среду; не продолжать трактовать этот прогон как TextKit 2 baseline.
6. **F-07:** перед открытием выполнить `shasum -a 256 TestData/generated/*`; после правок и
   закрытия повторить. Байты исходных документов и манифеста должны совпасть. Проверить также
   замену текста через Open и выход без сохранения.

Если Open не даёт прочитать файл, записать ошибку как **file access / App Sandbox** отдельно.
Не объявлять TextKit 2 непригодным на основании такого сбоя. Доступ выдаётся Open Panel на время
чтения; bookmarks, повторное открытие после перезапуска и запись на диск не исследуются.

## Ручные измерения

Фиксировать Mac/чип/RAM, точные macOS/Xcode, питание, фоновую нагрузку, размеры окна и шрифт
(стартовый content size 900×650, моноширинный системный 14 pt, перенос по ширине).

- По возможности три повторения: одинаковые файлы и действия, медиана и диапазон min…max.
- Холодный запуск и повторная загрузка — отдельные серии. Не считать системный файловый кеш
  очищенным только потому, что приложение перезапущено.
- Память: пустой редактор, после каждой загрузки, после серии правок, после повторных загрузок.
  Указать момент наблюдения и показатель: Activity Monitor Memory либо конкретный инструмент
  Instruments. Разные показатели не объединять в один ряд.
- Для проверки накопления памяти повторить одинаковую последовательность загрузок/правок,
  фиксировать число циклов. Сам по себе высокий watermark не доказывает утечку.
- Наблюдать фактическую готовность к вводу/прокрутке. Если достоверного численного метода нет,
  записать «субъективное наблюдение», а поле миллисекунд оставить «не измерено».
- Не снимать RAM/скорость по XCTest-процессу. Instruments-запуски маркировать отдельно от
  запусков только с Activity Monitor. Не смешивать Debug и Release.

Численных порогов нет. Финальный вердикт принадлежит владельцу проекта по результатам ручной
проверки и замеров; сборка и автотесты не подтверждают гипотезу автоматически.
