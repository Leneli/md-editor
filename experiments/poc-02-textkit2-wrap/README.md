# PoC-02 — TextKit 2 Long-line Word Wrap

Изолированное сравнение Word Wrap ON/OFF по разделу 7 `../../TECH_RESEARCH.md`.
Гипотеза H2: перенос усиливает задержки на одной мегабайтной строке. **H2 не подтверждена.**
Загрузка UTF-8 только в память, одно окно, TextKit 2. Open заменяет текст, закрытие отбрасывает
правки без сохранения. F02-01 (двойной пробел) и F03-01 (группировка Undo) не исправляются.

## Сборка и запуск

macOS 27.0+, arm64, Xcode 27.x; Swift/AppKit без внешних пакетов. Ad hoc подпись, App Sandbox,
user-selected read-only. Команды из `experiments/poc-02-textkit2-wrap/`:

```sh
xcodebuild -project PoC02.xcodeproj -scheme PoC02 -configuration Debug \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath DerivedData build
xcodebuild -project PoC02.xcodeproj -scheme PoC02 -configuration Debug \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath DerivedData test
xcodebuild -project PoC02.xcodeproj -scheme PoC02 -configuration Release \
  -destination 'platform=macOS,arch=arm64' -derivedDataPath DerivedData build
open DerivedData/Build/Products/Release/PoC02.app
```

`Experiment → Word Wrap: ON/OFF` переключает режим. Начальное состояние всегда ON, настройка
не сохраняется. Режим также виден в заголовке. Для измерения OFF включить его **в пустом окне**,
затем открыть файл. Одна и та же Release-сборка используется для обоих режимов.

`Experiment → Prepare Input at Document Midpoint` устанавливает курсор на ближайшую слева
границу Swift Character около середины UTF-16. Это учитывает суррогатные пары, комбинированные
знаки, ZWJ emoji и CRLF. Фактическое нулевое смещение после установки показано в заголовке
как **Prepared UTF-16 offset** и в журнале. Это значение на момент подготовки, не живой счётчик.
Команда не меняет текст, не очищает Undo и не вставляет символы. Сканирование текста и
прокрутка к курсору — подготовка; возврат команды не гарантирует завершения отрисовки.

## Отличия конфигурации

Исходники скопированы из PoC-01, общей изменяемой библиотеки нет. Сохранены загрузчик,
синхронное чтение/декодирование, текстовые флаги, Undo, шрифт, отступы, вертикальная настройка
и редкая диагностика редактирования (0,5 с). Добавлены меню эксперимента, настройка wrap,
подготовка курсора и логи режима/геометрии. `NSTextContainer.size` использует современное имя
того же свойства, которое в PoC-01 называлось `containerSize`.

| Параметр | ON | OFF |
|---|---|---|
| Начальный content size окна | 900×650 pt | 900×650 pt |
| Шрифт / inset | system monospaced 14 pt / 12×12 pt | Те же |
| `widthTracksTextView` | true | false |
| Ширина контейнера | Как в PoC-01: исходно content width; затем tracking ширины view с учётом inset | 16 777 216 pt |
| `isHorizontallyResizable` | false | true |
| `autoresizingMask` | width | пустая, шириной управляет текстовая система |
| Максимальная ширина view | greatestFiniteMagnitude | ширина контейнера + 2×inset |
| Горизонтальный scroller | false | true |
| Вертикальный scroller / autohide | true / true | Те же |
| Высота контейнера / вертикальное расширение | greatestFiniteMagnitude / true | Те же |

Сначала отключается tracking ширины, затем включается горизонтальный рост: два механизма
не должны управлять шириной друг друга одновременно. View не получает frame шириной
16 миллионов: AppKit расширяет область документа по мере обработки содержимого. В тестовой
среде это происходит лениво при запросе видимости дальнего участка. Возврат ON сбрасывает
ширину view к viewport. Текст, выделение и история Undo сохраняются; геометрия прокрутки меняется.
Нет clipping/truncation, ограничения числа строк, собственного layout manager или изменения
атрибутов документа ради OFF.

### Почему такая ширина OFF

Фикстура почти целиком состоит из ASCII `x` после короткого Unicode-префикса. При системном
моноширинном 14 pt её оценочная ширина около 8,7 млн pt. Контейнер 2^24 = 16 777 216 pt даёт
существенный запас и конечную, точно представимую величину. Тест измеряет 1000 `x` через
TextKit 2 и проверяет запас для миллиона с резервом на префикс, без layout мегабайтной строки.
Это обоснование для **данной фикстуры и шрифта**, не универсальная гарантия для произвольных
файлов. Реальные отсутствие переноса и достижимость конца стресс-файла остаются частью W-02.
Изменение шрифта/фикстуры требует новой проверки ширины.

## Диагностика и автоматические проверки

```sh
log stream --level info --style compact --predicate 'subsystem == "local.md-editor.PoC02"'
```

Контроль движка сохранён: явный `NSTextView(usingTextLayoutManager: true)`, запрос только
`textLayoutManager`, уведомления will/did-switch с фильтрацией по экземпляру. Логи содержат
wrap, textKit2, fallbackCount, uptime. Отдельные строки geometry содержат viewport, frame,
контейнер, шрифт, inset, scale и флаги. `switch-*` и `prepare-cursor-*` — **подготовка**.
Времена чтения/decode/установки строки не являются задержкой пользовательского ввода.
В приложении нет полного `ensureLayout`, `sizeToFit`, обхода layout-фрагментов или
хеширования всего документа на каждую правку.

Тесты: исходная конфигурация ON, безопасная диагностика, буквальный ввод, Unicode,
Undo/Redo/clipboard, ошибки загрузки, неизменность исходника, ON→OFF→ON, сохранение
выделения/Undo, подготовка курсора и хеши существующих фикстур. На строке из 1000 `x`
проверяются реальные line fragments, видимость каретки и правки в начале/середине/конце,
ширина области документа и возврат к переносу после resize. Полная разметка в тестовом
helper запрещена для текста длиннее 4096 UTF-16 units. Большие фикстуры проверяются
загрузчиком без NSTextView. Это сознательное ограничение, не автоматический PASS W-02/W-03.

XCTest target unhosted и без sandbox. Он не доказывает реальный доступ Open Panel, работу
меню, физический ввод или интерактивность Release. Нельзя снимать по XCTest показатели RAM/CPU.
Ошибки sandbox/testmanagerd относятся к среде/доступу и учитываются отдельно от TextKit 2.

## Обязательный допуск к A/B

1. Запустить PoC-01 и PoC-02 ON по очереди в Release, без debugger, в свежих процессах.
   Совместить условия: тот же файл/хеш, окно и **фактический viewport**, шрифт, scale,
   системные scrollers, нагрузка и питание. Не использовать helper PoC-02 как действие,
   которого нет в исходном прототипе, для прямого сопоставления этих двух приложений.
2. В ON проверить обычный файл; затем в отдельном процессе стресс-файл: медленный ввод/
   удаление и впервые посещаемые участки прокрутки, как в RESULTS_POC01.md. Сохранить наблюдения.
3. Если F04-01 не воспроизводится уже в ON, **не делать вывод о преимуществе OFF**. Проверить
   условия и отличия настройки, OS/SDK, layout/cache и сценария; результат A/B пока inconclusive.
   Старые CPU-числа PoC-01 не заменяют этот контроль.
4. Отдельный функциональный прогон OFF: начало, середина (helper) и конец (`Cmd+Right` для
   строки, `Cmd+Down` для документа); горизонтальная прокрутка, видимость каретки, вставка
   одного символа и удаление на каждой позиции. Убедиться, что строка одна и конец не обрезан.
   Проверить ON→OFF→ON, resize и обычный многострочный файл. Данные не сохранять.
5. Проверить textKit2=true/fallbackCount=0. Если OFF-геометрия неверна, сначала исправить её;
   плохой OFF ещё не доказывает ограничение движка. Эти проверки не входят в профилируемую серию.

## Протокол измерений

Сначала заполнить среду в RESULTS_POC02.md. Каждое измерение начинается новым процессом,
выбором режима в пустом окне, открытием ровно одного файла. Не смешивать повторное открытие
с первым; новый процесс не очищает файловый кеш ОС. Фиксировать PID и hash/версию сборки.

Для **каждой категории ниже**: минимум три стресс-прогона на режим, чередуя ON/OFF;
для контроля — три прогона обычного 1-МБ файла на режим. Если профилирование проводится
частями, явно отмечать, какие категории/повторы отсутствуют. Одна сборка, одинаковые условия.

- **Ввод/удаление.** Вызвать Prepare Input…, записать фактический UTF-16 offset, дождаться
  видимой каретки и окончания заметной работы UI. Затем начать запись Time Profiler.
  Набрать `abcdefghijklmnopqrst` посимвольно с одинаковым целевым темпом (например, 4 клавиши/с),
  пауза 2 с, 20 Backspace с тем же темпом. На timeline раздельно выделить ввод и удаление.
  Если приложение не успевает, не считать это точной задержкой каждой клавиши; описать очередь
  ввода/паузы и способ подачи событий. Ни переключение wrap, ни подготовка курсора в эти
  интервалы не входят. Не включать автоматическую вставку готовой строки в один вариант.
- **Undo/Redo.** Новый процесс, тот же режим/файл/смещение. До записи набрать ту же строку;
  число шагов предварительно установить функциональной проверкой. В измеряемом интервале
  выполнить Undo, паузу 2 с, Redo. Зафиксировать фактически отменённый/восстановленный текст
  и число действий. Не вызывать `breakUndoCoalescing()` из helper ради выравнивания группировки.
  Если группы/исходные состояния различаются, прогон не сопоставим.
- **Прокрутка.** Отдельный свежий процесс; начать в начале документа без helper середины.
  Исследовать впервые посещаемые участки, затем повторное посещение отдельно. Для ON записывать
  вертикальную, для OFF горизонтальную траекторию и длительность. Направления не эквивалентны:
  суммарное CPU этих двух записей не является коэффициентом ускорения одного сценария.

Записывать CPU main thread только в выбранных сопоставимых интервалах, горячие стеки,
Hangs и измеренную длительность зависаний, субъективную отзывчивость. Total CPU всей записи
не доказывает преимущество режима. Median/min/max — только для сравнимых метрик. Если временные
границы действий нельзя восстановить, не выдавать численное сравнение за строгое.

Time Profiler можно подключить к уже подготовленному процессу. Если запись начата раньше,
исключить load/switch/prepare/settling при выборе диапазона. Фактическую методику записать.
Одинаковое смещение фиксирует логическую позицию, но не одинаковую историю viewport;
helper сам прогревает путь к каретке. Этот прогрев одинаков по процедуре и явно отмечается.

Memory основного процесса — вторичная метрика, фиксировать инструмент, момент и условия.
`.trace` сохранять сразу после Stop с именем, содержащим файл/режим/категорию/повтор;
правило `*.trace` уже есть в корневом .gitignore. После серии снова проверить хеши фикстур.

## Готовность и решение

W-01…W-06 проверяют реализацию и данные; W-07 требует заполненного протокола и профилей.
Пустая форма результатов и успешные тесты означают готовность к ручному опыту, а не его завершение.
Повторяемое улучшение OFF в проблемных действиях с профилем поддерживает H2; отсутствие
улучшения не поддерживает её. Fallback, неверная геометрия, отсутствие исходной проблемы в ON
или несопоставимые прогоны дают inconclusive. Продуктовая стратегия wrap и выбор движка
принимаются владельцем отдельно. Коммит/push без разрешения не выполняются.
