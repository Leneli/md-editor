## Что подтверждают тесты

| Проверка | Результат / границы |
|---|---|
| Исходная конфигурация ON | Совпадают заданные в PoC-01 окно 900×650, шрифт 14 pt, inset 12, tracking/resize/scroller-флаги и размер контейнера; это не доказательство воспроизведения лагов |
| Layout строки 1000 `x` | ON — несколько line fragments; OFF — один, содержащий все 1000 UTF-16 units |
| OFF начало/середина/конец | Каретка на offset 0/500/1000 попадает в видимую область после запроса прокрутки; вставка и удаление сохраняют исходный текст |
| Размер области документа | После посещения конца ширина включает строку и меньше огромного предела контейнера |
| Запас ширины стресс-файла | Ширина 1000 `x` ×1000 +4096 pt меньше 16 777 216 pt; это расчётный запас для фиксированного хвоста, не layout всей мегабайтной строки |
| Возврат ON / resize | Снова несколько визуальных строк; более узкое окно увеличивает их число |
| Явные переносы в OFF | `First\nSecond\nThird` остаётся тремя визуальными строками |
| ON→OFF→ON и подготовка | Текст/выделение сохранены, Undo остаётся доступен, после подготовки Undo/Redo корректны |
| Unicode midpoint | Пустой текст, ASCII, комбинированный знак, emoji с ZWJ/модификатором, флаг, CRLF, семейный emoji — валидные границы Character |
| Базовые тесты из PoC-01 | Буквальная text-input вставка, Unicode, Undo/Redo, private pasteboard, ошибки загрузки, сброс Undo, неизменность файла прошли |
| Фикстуры 1 МБ | Оба файла прочитаны загрузчиком, размер/хеш/UTF-8 проверены; в этом тесте NSTextView не создаётся |
| Диагностика | В проверенных сценариях TextKit 2 активен, fallbackCount=0, 100 повторных запросов состояния не вызвали переход |

Полный `ensureLayout` используется только helper теста со строгим пределом 4096 UTF-16 units.
В коде приложения такого вызова нет. Никакой принудительной полной разметки 1-МБ строки для
автотестов не выполнялось. Unhosted тесты не проверяют жизненный цикл app delegate и sandboxed UI.

## Выявленные и исправленные проблемы

1. NSString composed-character lookup на CRLF не совпал с границей Swift Character.
   Использован линейный проход по Character до середины UTF-16; CRLF и emoji тестируются.
   Стоимость этого прохода относится только к подготовке, а не обработке каждого ввода.
2. При малом layout-тесте NSTextView расширял frame лениво: `ensureLayout` менеджера ещё не
   означал, что viewport обновил размер document view. Проверка выполняется после реального
   запроса видимости конца; подтверждены и видимость каретки, и размер области, и правки.
   Принудительный `sizeToFit` приложения ради теста не добавлялся.
3. Xcode выводил системное предупреждение IDELaunchSession и сообщение пропуска AppIntents
   metadata; sandboxed Release build также выводил ошибки недоступности CoreSimulator.
   Итоговые build/test успешны; Swift compiler warnings в финальных логах не обнаружены.

## Запуск и непроверенное

Команда `open` финального Release `.app` завершилась с кодом 0. Затем Computer Use сообщил:
**“Computer Use was not approved to use PoC02”**. Управление/осмотр UI не выполнялись,
другие средства обхода этого ограничения не использовались. Успех `open` не считается
подтверждением видимого окна, меню или пользовательской отзывчивости.

Остаются ручными и **не получили PASS**:

- Воспроизведение F04-01 в PoC-02 ON при сопоставимых с PoC-01 условиях. До этого A/B-вывод
  запрещён протоколом. Если ON уже быстрый, сначала установить, что изменилось.
- Реальная 1-МБ строка OFF: отсутствие переноса/обрезания; просмотр, прокрутка и редактирование
  начала/середины/конца. Малый тест и запас ширины не заменяют эту проверку.
- Загрузка обеих полных фикстур через Open Panel в каждом режиме, cancel/ошибки доступа,
  физический ввод, меню, app lifecycle и работа sandboxed-приложения.
- Отдельные профили/интервалы ввода, удаления, Undo, Redo и прокрутки; повторения, Hangs,
  сопоставимые main-thread CPU, память и точные условия. Численных результатов H2 нет.
- Поведение при настоящем fallback не наблюдалось и намеренно не провоцировалось.

Пользовательская форма RESULTS_POC02.md оставлена незаполненной. Отдельные проблемы sandbox/
доступа не трактуются как ограничения TextKit 2. F02-01/F03-01 остаются за пределами этой задачи.
